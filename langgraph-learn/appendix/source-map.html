附录 D · 源码地图

这张地图按「你为什么会打开它」组织，不按目录字母序。 找不到实现时，先判断它属于建图、执行、状态、持久化还是 Agent 封装。

怎么读源码

  • 先看公开 API 的 docstring，再看它调用的内部函数。
  • 遇到「为什么这样」时，看类型定义与默认值，不要只看实现。
  • 每读一个模块，回到本站对应章节跑一个最小例子。

graph：建图 API

StateGraph state.py:131 负责收集节点、边与 schema；add_node state.py:376、 add_edge state.py:928、 add_conditional_edges state.py:982 都只是记录；compile state.py:1177 才生成执行器。

message.py message.py:64 里的 add_messages 与 MessagesState 是消息状态的入口。

pregel：执行引擎

Pregel main.py:456 是编译后的执行器。入口方法： invoke main.py:3870、 stream main.py:2705、 get_state main.py:1460、 update_state main.py:2613。 checkpoint 写入在 _loop.py _loop.py:768， 递归上限在 _loop.py:1917。

checkpoint：持久化

契约在 BaseCheckpointSaver base/__init__.py:199； 内存版 memory/__init__.py:34、 SQLite sqlite/__init__.py:49、 Postgres postgres/__init__.py:45。 Store 契约在 store/base/__init__.py base/__init__.py:708。

prebuilt：Agent 与 ToolNode

create_react_agent chat_agent_executor.py:278 在 1.2.20 是维护模式；ToolNode tool_node.py:630 与 tools_condition tool_node.py:1616 仍是工具循环的常用组件。

推荐阅读顺序

  1. graph/state.py 的公开方法签名。
  2. pregel/main.py 的 invoke / stream 与 get_state。
  3. pregel/_loop.py 的 checkpoint 与递归上限。
  4. checkpoint/base 的 get_tuple / put / list。
  5. prebuilt/tool_node.py 的工具执行。
