附录 B · 报错速查

这一页按「现象 → 原因 → 改法」组织。先看错误文本属于哪一层， 再去对应章节补背景；不要靠改提示词碰运气。

怎么用

  • 先定位层：建图、状态、运行时、持久化、工具、部署。
  • 再看错误文本里有没有类名或字段名，直接搜本页。
  • 最后回到章节的最小例子复现，确认改法真的生效。

编译与图结构

StateGraph object is not callable

因为你还没 compile()。改成先编译，再 invoke。

节点不存在 / 无效边

因为add_edge 或条件边指向了未注册的名字。改成核对 add_node 的名字与路径映射。

图没有出口

因为最后一条边没连到 END。改成给终止节点加 add_edge("last", END)。

状态与 reducer

InvalidUpdateError

你会看到errors.py:92。因为同一 superstep 多个节点写了同一个没有 reducer 的字段。改成加 reducer，或让节点写不同字段。

消息只剩最后一条

因为字段没有声明 add_messages，默认覆盖。改成继承 MessagesState 或手写 Annotated[list, add_messages]。

EmptyInputError

你会看到errors.py:138。因为输入为空或不满足 schema。改成传入至少一个 State 字段，并检查必填字段。

运行时与持久化

GraphRecursionError

你会看到errors.py:69。因为循环没有业务停止条件，撞到递归上限。改成在路由函数里加计数 / 完成判定，并把上限当兜底。

恢复时报缺少 checkpointer

你会看到Cannot use Command(resume=...) without checkpointer _loop.py:1026。因为中断状态没地方存。改成编译时挂 checkpointer。

多轮对话不记得上一次

因为没有传同一个 thread_id。改成所有调用都带 {"configurable": {"thread_id": ...}}。

GraphInterrupt

你会看到errors.py:104。因为这是 interrupt 的内部冒泡，不是业务失败。改成不要捕获它当异常；按暂停流程处理，用 Command(resume=...) 恢复。

工具与模型

模型不调用工具

因为没有 bind_tools，或工具描述太含糊。改成绑定工具 schema，并把描述写清输入 / 输出 / 场景。

工具结果模型看不到

因为结果没写回 messages，而是放进了自定义字段。改成用 ToolMessage 追加到 messages。

工具异常导致整图失败

因为异常直接冒泡。改成在工具内捕获并返回可读错误文本，或按业务决定是否重试。

部署

langgraph dev 能跑，生产不行

因为dev 是本地模式，没有持久化与鉴权。改成用 langgraph up 或自建 FastAPI + Postgres。

多副本历史丢失

因为用了 InMemorySaver。改成Postgres checkpointer / store。

同一 thread 重复执行

因为没有会话级串行。改成加锁 / 队列 / 409，或让前端复用同一个订阅。
