15 · 测试与可观测性：假模型、图断言与 LangSmith

图的行为不能只靠「跑一遍看看」。这一章用假模型把模型调用变成确定性输入， 用图级断言检查「走了哪条边、state 变成什么」，再把追踪接上。

读完你能做到

  • 用假模型替换真实 LLM，让测试不访问网络
  • 断言图走了哪条路径、最终 state 是什么
  • 用 stream 调试节点顺序与更新内容
  • 接 LangSmith / OpenTelemetry，看到每次运行的 trace 与 token

先说为什么：图的行为要能断言

一次真实模型调用既慢又不确定。测试应该断言「给定输入，图是否走到正确的节点、 是否更新了正确的字段」，而不是断言模型输出的自然语言。 假模型让这部分变成纯函数测试。

最小可跑：假模型跑通一张图

from langchain_core.language_models.fake_chat_models import FakeListChatModel


model = FakeListChatModel(responses=["这是固定回复"])

# 把 model 当成普通 chat model 塞进节点
def agent(state: dict) -> dict:
    return {"messages": [model.invoke(state["messages"])]}

假模型只返回预设文本，不访问网络。需要工具调用时，可以用 FakeMessagesListChatModel 返回带 tool_calls 的 AIMessage。

图级断言：看 state、看路径

result = graph.invoke({"question": "我要退款", "route": "", "answer": ""})
assert result["route"] == "billing"
assert "退款" in result["answer"]

# 看走过哪些节点
steps = [u for u in graph.stream(
    {"question": "我要退款", "route": "", "answer": ""},
    stream_mode="updates",
)]
assert any("billing" in step for step in steps)
断言层看什么适合
节点单元测试输入 state → 输出 partial state纯函数、工具包装
图级断言最终 state、走过的节点路由、循环、终止
集成测试真实模型 / 真实存储发布前冒烟

追踪与指标

LangSmith 通过环境变量开启，会自动记录图、节点、模型与工具调用。 没有 LangSmith 时，可以用 OpenTelemetry 或自己包一层节点装饰器， 至少记录：节点名、耗时、输入 / 输出大小、token、错误。

  • trace 里先看「走了哪条边」，再看「哪个节点慢」。
  • token 指标按节点聚合，定位是哪个 prompt 在烧钱。
  • 错误按节点分类：模型 429、工具异常、状态冲突、checkpoint 失败。

图级测试

现象原因改法

再深入一点：实现细节与边界

用 updates 断言路径

steps = [
    update
    for update in graph.stream(inputs, stream_mode="updates")
]
nodes = [next(iter(update)) for update in steps if update]
assert nodes == ["classify", "billing"]

假模型的两种形态

替身用途
FakeListChatModel按顺序返回固定文本
FakeMessagesListChatModel返回带 tool_calls 的 AIMessage
自定义 BaseChatModel需要精确控制 metadata / usage

观测的最小集合

  • 每次运行的 trace id 与 thread id。
  • 每个节点的耗时、输入 / 输出大小、错误。
  • 模型 token、工具调用次数、重试次数。
  • HITL 暂停时长与恢复结果。

陷阱与窍门

用真实模型做单元测试

你会看到测试慢、偶尔失败、账单上涨。因为模型不确定。改成假模型跑单测，真实模型只做发布前冒烟。

只断言最终字符串

你会看到模型换个措辞测试就红。因为断言太脆。改成断言 state 字段、路径、工具调用次数。

没有 trace 就调多 Agent

你会看到不知道谁改了 state。因为多 Agent 的路由不可见。改成先接 trace，再调拓扑。

自检三问

  1. 为什么单元测试要用假模型？它替代了哪一层？
  2. 图级断言至少应该看哪两类信息？
  3. trace 里定位「谁改坏了 state」的顺序是什么？
