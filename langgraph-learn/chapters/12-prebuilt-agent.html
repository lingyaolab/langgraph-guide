12 · 预构建 ReAct Agent：create_react_agent 能做什么、不能做什么

create_react_agent 把「模型节点 + 工具节点 + 条件边」打包成一张图， 十行就能跑。但 1.2.20 的方向说明写得很清楚：prebuilt 是维护模式， 新 Agent 开发应该往上一层（harness）走，或自己显式搭图。这一章讲它的能力与边界。

读完你能做到

  • 用 create_react_agent 十行搭一个带工具的 Agent
  • 说清它内部的两三个节点与工具循环
  • 接入 checkpointer、store 与 interrupt
  • 判断什么时候该自己搭图，而不是继续加参数

先说为什么：预构建是起点，不是终点

create_react_agent chat_agent_executor.py:278 的价值是「让你五分钟看到工具循环」，不是「覆盖所有生产需求」。 一旦你要自定义路由、状态、多个 Agent、复杂的 HITL，显式搭图更清楚。

最小可跑：十行一个 Agent

from langchain.chat_models import init_chat_model
from langchain_core.tools import tool
from langgraph.prebuilt import create_react_agent


@tool
def get_weather(city: str) -> str:
    """查询指定城市的天气。"""
    return f"{city}: 18C, sunny"


model = init_chat_model("deepseek:deepseek-chat")
agent = create_react_agent(model, [get_weather])

out = agent.invoke({"messages": [("user", "北京天气如何？")]})
print(out["messages"][-1].content)

内部图：模型节点 + 工具节点

它生成的图与 11 章手写的几乎一样： agent 节点调模型，tools 节点是 ToolNode， 条件边用 tools_condition，工具执行后回到 agent。 区别是它还处理了 prompt、结构化输出、pre-model hook 等参数。

参数作用注意
modelChatModel 或模型名工具要绑定后才能调用
tools工具列表 / ToolNode空列表就是纯聊天
prompt系统提示或动态 prompt不要和 state 里的 messages 冲突
checkpointer持久化多轮 / HITL 必需
store长期记忆跨 thread 共享
interrupt_before在节点前暂停调试 / 人工确认

扩展：checkpointer、store、interrupt

from langgraph.checkpoint.memory import InMemorySaver

agent = create_react_agent(
    model,
    [get_weather],
    checkpointer=InMemorySaver(),
)

config = {"configurable": {"thread_id": "u-1"}}
agent.invoke({"messages": [("user", "北京天气如何？")]}, config)

interrupt_before=["tools"] 可以在工具执行前暂停， 适合「删除 / 写操作」的人工确认。但更细粒度的确认， 建议在工具节点内部用 interrupt()（07 章）。

边界：什么时候自己搭

  • 需要自定义状态字段与 reducer，而不只是 messages。
  • 需要多 Agent 路由、子图或非线性的控制流。
  • 需要在工具前后插入审计、权限、预算等节点。
  • 需要精确控制中断点、恢复语义与前端事件。
  • 框架方向：prebuilt 是维护模式，新 Agent 能力应放在 harness 层，而不是继续堆参数。
把 create_react_agent 当生产架构

它适合原型与学习。生产里一旦出现多租户、复杂权限、长任务恢复， 显式图或 harness 层的可解释性更好。

工程实践：三种写法与排查

prebuilt 的三种装配

agent = create_react_agent(model, tools)
agent = create_react_agent(model, tools, checkpointer=saver)
agent = create_react_agent(model, tools, checkpointer=saver, store=store)

需要自定义时的替代

builder.add_node("agent", agent)
builder.add_node("tools", ToolNode(tools))
builder.add_edge(START, "agent")
builder.add_conditional_edges("agent", tools_condition)
builder.add_edge("tools", "agent")
现象原因改法
工具数量不匹配model 已 bind 另一组工具只传未绑定模型或对齐
暂停后无法恢复没挂 checkpointer挂上再 interrupt
越改越复杂把 prebuilt 当架构改显式图
行为不稳定流程写在 prompt流程放节点 / 边

再深入一点：实现细节与边界

create_react_agent 的常用参数

参数作用建议
modelChatModel 或模型名未绑定工具时会自动绑定
tools工具列表或 ToolNode与模型绑定工具保持一致
prompt系统提示 / 动态提示不要把流程写进提示词
checkpointer持久化多轮与 HITL 必需
store长期记忆跨 thread 共享
interrupt_before节点前暂停调试 / 粗粒度确认

什么时候显式搭图

需要自定义 state、多个 Agent、复杂 HITL、审计节点或非 messages 状态时， 直接把 11 章的图抄过来改，比继续给 prebuilt 加参数更可控。 

builder = StateGraph(MessagesState)
builder.add_node("agent", agent)
builder.add_node("tools", ToolNode(tools))
builder.add_edge(START, "agent")
builder.add_conditional_edges("agent", tools_condition)
builder.add_edge("tools", "agent")

版本方向

1.2.20 的仓库说明把 prebuilt 定为维护模式：修 bug，不加新 Agent 能力。 新项目应把 LangGraph 当运行时，Agent 层用 harness 或显式图。

陷阱与窍门

模型已经 bind_tools，但 tools 参数不一致

你会看到 ValueError: Number of tools in the model.bind_tools() and tools passed to create_react_agent must match。因为绑定工具与传入 tools 不是同一组。改成只传未绑定的模型让 create_react_agent 自动绑定，或保证两边一致。

没有 checkpointer 却用 interrupt_before

你会看到暂停后无法恢复。因为暂停状态没有持久化。改成同时挂 checkpointer。

把所有逻辑塞进 prompt

你会看到行为不稳定、无法测试。因为流程应该在节点/边里，不在自然语言里。改成显式节点与条件边。
