21 · Runtime Context 与配置：请求级上下文不要放全局

多用户服务里，最容易出的 bug 是「上一个请求的 user_id 泄漏到下一个请求」。 LangGraph 用 context_schema + Runtime 把请求级上下文显式传进节点， 而不是藏在全局变量或提示词里。

读完你能做到

  • 用 context_schema 定义请求级上下文
  • 在节点里通过 Runtime 读取 context 与 store
  • 用 configurable 传 thread_id 等运行配置
  • 区分「图状态」「运行上下文」「长期存储」三层

先说为什么：全局变量在并发下一定串

Web 服务同时处理多个请求。把 current_user 放在模块全局变量里， 两个请求交错时就会互相覆盖。上下文必须是「每次调用一份」的， 并且只能通过显式参数进入节点。

最小可跑：context_schema + Runtime

from dataclasses import dataclass

from langgraph.graph import END, START, StateGraph
from langgraph.runtime import Runtime


@dataclass
class Context:
    user_id: str
    tenant_id: str


class State(dict):
    pass


def whoami(state: State, runtime: Runtime[Context]) -> dict:
    ctx = runtime.context
    return {"user": ctx.user_id, "tenant": ctx.tenant_id}


builder = StateGraph(State, context_schema=Context)
builder.add_node("whoami", whoami)
builder.add_edge(START, "whoami")
builder.add_edge("whoami", END)
graph = builder.compile()

out = graph.invoke({}, context=Context(user_id="alice", tenant_id="t1"))
print(out)

context_schema state.py:212 声明上下文类型；Runtime runtime.py:125 在节点里提供 context、store、stream_writer 等运行时能力。

configurable：thread 与自定义配置

config = {
    "configurable": {
        "thread_id": "u-1",
        "model": "deepseek-chat",
    }
}
graph.invoke({}, config, context=Context(user_id="alice", tenant_id="t1"))

configurable 是「运行配置」，会进入 checkpoint 与追踪； context 是「本次调用的依赖」，适合用户、租户、数据库连接等不适合持久化的东西。

三层上下文不要混

层放什么生命周期
State对话消息、任务中间结果thread 级，进 checkpoint
Runtime Contextuser_id、tenant_id、请求级客户端单次调用
Store用户偏好、跨会话事实跨 thread

工程实践：三种写法与排查

三种上下文来源

state["user_note"]          # 业务数据
runtime.context.user_id     # 请求级身份
config["configurable"]      # thread / 运行配置
现象原因改法
并发串号全局 current_userRuntime Context
checkpoint 里有密钥身份/密钥放 state只放 id / 引用
恢复后 context 丢失context 不持久化需要持久化的放 config / state
读不到 thread_id没传 config所有调用带同一 config

再深入一点：实现细节与边界

Runtime 里还有什么

属性用途
context本次调用的用户 / 租户 / 客户端
store长期记忆
stream_writer发自定义事件
previous上一次运行的信息
execution_info运行元数据

context 与 config 的取舍

需要进入 checkpoint / trace 的放 configurable； 不应持久化的依赖（数据库连接、请求级客户端）放 context。 两者都能在节点里读到，但生命周期不同。

并发验证

async def run(user):
    return await graph.ainvoke({}, context=Context(user_id=user, tenant_id="t"))

await asyncio.gather(run("alice"), run("bob"))

陷阱与窍门

把用户身份放进 state

你会看到身份被写进 checkpoint，甚至被共享。因为state 会持久化。改成身份放 Runtime Context，state 只放业务数据。

在工具里读全局 current_user

你会看到并发串号。因为全局变量没有请求隔离。改成通过 Runtime 或工具参数显式传。

把数据库连接放进 state

你会看到序列化失败或连接泄漏。因为state 要写 checkpoint。改成连接放 Runtime Context，state 只放 id。
