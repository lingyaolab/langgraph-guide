11 · LangChain 集成：模型、工具与 ToolNode

LangGraph 本身不带模型与工具，它只负责编排。真实应用里， 模型来自 LangChain 的 chat model，工具通过 bind_tools 暴露， ToolNode 负责执行。这一章把这条接缝讲清。

读完你能做到

  • 用 init_chat_model 创建模型，并用 bind_tools 暴露工具
  • 用 ToolNode 执行工具调用，把 ToolMessage 写回消息
  • 用 tools_condition 做「有工具就去工具节点，没有就结束」的路由
  • 说清模型返回 tool_calls 后图为什么能回到模型节点

先说为什么：LangGraph 不带模型，只带编排

这是最容易混的一层：StateGraph 不知道什么是 LLM； ChatModel 也不知道什么是图。两者通过「节点里调用模型」和 「条件边看 tool_calls」连接。理解这条边界，换模型、换工具都不会动图结构。

最小可跑：模型 + 工具 + 图

from langchain.chat_models import init_chat_model
from langchain_core.tools import tool
from langgraph.graph import END, START, MessagesState, StateGraph
from langgraph.prebuilt import ToolNode, tools_condition


@tool
def get_weather(city: str) -> str:
    """查询指定城市的天气。"""
    return f"{city}: 18C, sunny"


model = init_chat_model("deepseek:deepseek-chat").bind_tools([get_weather])


def agent(state: MessagesState) -> dict:
    return {"messages": [model.invoke(state["messages"])]}


builder = StateGraph(MessagesState)
builder.add_node("agent", agent)
builder.add_node("tools", ToolNode([get_weather]))
builder.add_edge(START, "agent")
builder.add_conditional_edges("agent", tools_condition)
builder.add_edge("tools", "agent")

graph = builder.compile()
out = graph.invoke({"messages": [("user", "北京天气如何？")]})
print(out["messages"][-1].content)

ToolNode 与 tools_condition

ToolNode tool_node.py:630 是一个预构建节点：它读最后一条 AIMessage 的 tool_calls， 逐个执行，把结果包装成 ToolMessage 追加回 messages。 tools_condition tool_node.py:1616 是配套路由：有 tool_calls 就去 "tools"，没有就去 END。

对象职责不做什么
model.bind_tools把工具 schema 告诉模型不执行工具
ToolNode执行 tool_calls，写回 ToolMessage不决定下一步
tools_condition根据 tool_calls 选边不执行工具
agent 节点调模型，返回 AIMessage不解析工具结果

工具消息怎么回到模型

工具执行完，ToolMessage 会带着 tool_call_id 写回 messages。 模型下一轮看到这条消息，就知道「哪个调用返回了什么」。 图通过 add_edge("tools", "agent") 回到模型节点，形成循环； tools_condition 在没有新工具调用时结束循环。

工具结果不要只放在 state 的自定义字段

模型只读 messages。把工具结果放在 last_tool_result 这种字段里， 模型看不到；除非你在下一轮手动拼进消息。

再深入一点：实现细节与边界

工具错误处理

from langgraph.prebuilt import ToolNode

tools = ToolNode([get_weather], handle_tool_errors=True)
# 也可以传字符串、异常类型或自定义函数，决定错误如何回到模型

handle_tool_errors tool_node.py:757 默认会把可预期的工具错误转成 ToolMessage； 设成 False 则让异常冒泡。

工具返回 Command

工具不一定要只返回文本。返回 Command(update=..., goto=...) 可以让工具直接改变图的走向，例如「查询完成后跳到汇总节点」。 这属于高级用法，先确认普通 ToolMessage 不够用。

消息键不是 messages 时

ToolNode([get_weather], messages_key="chat_history")

state 里的消息字段叫别的名字时，ToolNode 与 tools_condition 都要同步指定 messages_key，否则它们读不到工具调用。

陷阱与窍门

忘记 bind_tools

你会看到模型永远不调用工具。因为schema 没传给模型。改成model.bind_tools([...])，并把绑定后的模型放进节点。

工具名与路由名不一致

你会看到tools_condition 指向的节点不存在。因为默认节点名是 "tools"。改成把 ToolNode 注册为 "tools"，或用自定义路由。

工具里抛异常

你会看到整张图失败，而不是模型收到错误。因为ToolNode 默认让异常冒泡。改成在工具里捕获并返回可读错误文本，让模型换方案。
