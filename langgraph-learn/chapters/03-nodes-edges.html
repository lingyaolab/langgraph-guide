03 · 节点、边与条件路由：谁决定下一步

图的控制流不是写死的 if/else，而是「当前节点返回什么 → 路由函数选哪条边」。 这一章把普通边、条件边和循环讲清楚，并给出停止条件的写法。

读完你能做到

  • 写出符合签名的节点函数，知道它可以同步也可以异步
  • 用 add_conditional_edges 做二选一与多路路由
  • 用路径映射把路由结果翻译成节点名
  • 给循环设置明确的停止条件，避免 GraphRecursionError

先说为什么：图把控制流变成数据

当分支条件来自模型输出、工具结果或人工确认时，把它写进 Python 的 if 会让流程不可见、不可回放。条件边把「下一步是谁」变成一次可观察的路由决策， 也让 checkpoint 能记录「当时为什么走这条」。

最小可跑：一个二选一的路由

from typing import Literal, TypedDict

from langgraph.graph import END, START, StateGraph


class State(TypedDict):
    question: str
    route: str


def classify(state: State) -> dict:
    route = "billing" if "退款" in state["question"] else "general"
    return {"route": route}


def billing(state: State) -> dict:
    return {"question": state["question"] + " → 退款流程"}


def general(state: State) -> dict:
    return {"question": state["question"] + " → 通用回答"}


def pick(state: State) -> Literal["billing", "general"]:
    return state["route"]  # type: ignore[return-value]


builder = StateGraph(State)
builder.add_node("classify", classify)
builder.add_node("billing", billing)
builder.add_node("general", general)
builder.add_edge(START, "classify")
builder.add_conditional_edges("classify", pick, ["billing", "general"])
builder.add_edge("billing", END)
builder.add_edge("general", END)

graph = builder.compile()
print(graph.invoke({"question": "我要退款", "route": ""}))

节点：输入 state，输出 partial state

节点就是一个普通函数（或 async 函数），第一个参数是当前 state，返回值是要合并的字段。 节点名在 add_node state.py:376 时注册，之后所有边都引用这个名字。

节点不要返回完整 state

只返回你改的字段。返回完整 state 会把没改的字段也写一遍， 在并行场景下容易触发「同一字段被多个节点更新」的冲突。

边：普通边与条件边

普通边用 add_edge state.py:928， 条件边用 add_conditional_edges state.py:982。 条件边包含三部分：源节点、路由函数、路径映射（可选）。 

builder.add_conditional_edges(
    "classify",
    pick,
    {
        "billing": "billing",
        "general": "general",
        "unknown": END,
    },
)

路由函数返回的是「路径 key」，映射把它翻译成节点名。不写映射时， 返回值必须直接等于节点名。入口与出口也可以显式设置： set_entry_point state.py:1079、 set_finish_point state.py:1116。

循环：什么时候必须停

条件边可以指回上游，形成循环。图不会自动判断「该停了」， 你需要在路由函数里给出终止路径，同时依赖框架的递归上限兜底。 超过上限会抛 GraphRecursionError errors.py:69。 

class LoopState(TypedDict):
    count: int
    answer: str


def work(state: LoopState) -> dict:
    return {"count": state["count"] + 1, "answer": "done"}


def should_continue(state: LoopState) -> str:
    return "work" if state["count"] < 3 else END
递归上限不是业务停止条件

上限是兜底，不是设计。用业务字段（次数、状态、是否拿到结果）决定是否继续； 否则你会得到「跑满上限才报错」的慢失败。

陷阱与窍门

路由函数返回了节点名之外的值

你会看到编译或运行时提示无效路径。因为返回值没有对应映射。改成补齐映射，或让返回值严格等于节点名。

条件边从 START 出发

你会看到图不知道入口该走哪。因为START 的路由通常用 add_conditional_edges(START, ...)，但要确保每个分支都能到 END。改成先用一个入口节点收口，再加条件边。

循环里没有更新判断字段

你会看到永远停不下来。因为路由函数读的字段一直没变。改成在节点里更新计数或状态，再让路由读它。
