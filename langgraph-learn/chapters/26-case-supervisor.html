26 · 案例四：Supervisor 研究助手

需求：一个研究任务，先查资料，再写初稿，最后审查；审查不通过要返工。 这个案例用 Supervisor 路由与 handoff，把多角色协作装进一张图。

读完你能做到

  • 用 Supervisor 决定下一步交给谁
  • 用 Command(update=..., goto=...) 做 handoff
  • 用轮次上限与验收条件防止无限返工
  • 估算多 Agent 的 token 成本

先说为什么：多 Agent 是职责隔离

Researcher 需要检索工具，Writer 需要写作提示，Reviewer 需要审查标准。 把它们拆开，提示词与工具面更清晰；但每多一个 Agent，就多一份上下文与成本。

案例：一次带返工的研究

supervisor → researcher（查资料）
           → writer（写初稿）
           → reviewer（审查）
           → 不通过：回到 writer（返工）
           → 通过：END

装配：共享 state 与轮次

from typing import Annotated, Literal, TypedDict
from operator import add

from langgraph.graph import END, START, StateGraph
from langgraph.types import Command


class State(TypedDict):
    task: str
    notes: Annotated[list[str], add]
    draft: str
    review: str
    owner: str
    rounds: int


def supervisor(state: State) -> Command:
    if state["rounds"] >= 6:
        return Command(update={"owner": "END"}, goto=END)
    if not state["notes"]:
        return Command(update={"owner": "researcher"}, goto="researcher")
    if not state["draft"]:
        return Command(update={"owner": "writer"}, goto="writer")
    if state["review"] != "pass":
        return Command(update={"owner": "writer", "rounds": state["rounds"] + 1}, goto="writer")
    return Command(update={"owner": "END"}, goto=END)


def researcher(state: State) -> Command:
    return Command(update={"notes": ["资料 A", "资料 B"]}, goto="supervisor")


def writer(state: State) -> Command:
    return Command(update={"draft": "基于资料的初稿"}, goto="reviewer")


def reviewer(state: State) -> Command:
    ok = len(state["draft"]) > 5
    return Command(update={"review": "pass" if ok else "revise"}, goto="supervisor")


builder = StateGraph(State)
for name, fn in [("supervisor", supervisor), ("researcher", researcher), ("writer", writer), ("reviewer", reviewer)]:
    builder.add_node(name, fn)
builder.add_edge(START, "supervisor")
builder.add_edge("supervisor", END)

graph = builder.compile()

Supervisor 每次被调用都重新看 state，决定下一步。Worker 干完回到 supervisor， 而不是直接连下一个 Worker；这样路由逻辑集中在一处。

handoff：控制权怎么转

Command(update=..., goto=...) types.py:843 同时写状态与跳转。它适合「我知道下一步是谁」的场景； 如果只是根据 state 选边，条件边更简单。

成本与失败边界

风险控制
无限返工rounds 上限 + 明确验收
上下文爆炸只共享 notes / draft，不共享完整推理
成本翻倍限制 Agent 数，先单 Agent 验证
路由错Supervisor 用结构化输出 / 规则

陷阱与窍门

Worker 直接连 Worker

你会看到路由逻辑散落，难以追踪。因为没有中心决策。改成Worker 回到 supervisor。

没有轮次上限

你会看到writer 与 reviewer 互相踢皮球。因为验收条件不稳定。改成加 rounds 与 END。

共享全部 messages

你会看到每个 Agent 都看到别人的完整推理。因为共享 state 太大。改成只共享 notes / draft。

自检三问

  1. 为什么 Worker 应该回到 Supervisor，而不是直接连下一个 Worker？
  2. 返工循环靠什么停止？
  3. 多 Agent 共享哪些字段最合适？

40 分钟动手练习

  1. 让 reviewer 第一次返回 revise，观察 writer 返工后通过。
  2. 把 rounds 上限改成 2，确认超限后结束。
  3. 把 notes 改成工具检索，测量一次任务的 token 消耗。
