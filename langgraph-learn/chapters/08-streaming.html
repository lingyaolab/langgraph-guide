08 · 流式：stream_mode 与前端事件

流式不是「把最终结果分块发出去」，而是选择看哪一层： 每个节点的 state 更新、每条消息的 token、每个任务的开始结束，或你自己的自定义事件。 这一章把五种 stream_mode 的语义与前端契约讲清。

读完你能做到

  • 用 stream_mode="values" 看每一步后的完整 state
  • 用 "updates" 看节点返回的局部更新，用 "messages" 看 token
  • 用 "custom" 从节点内部发自定义事件
  • 把流式事件桥接到 SSE，并处理取消与断线

先说为什么：一次返回和一条事件流

invoke 只给你最终 state，中间发生了什么你看不到。 stream 把执行过程拆成事件：前端可以边生成边显示， 后端可以在每个节点后做审计，测试可以断言「走过哪条边」。

最小可跑：逐 token 打印

from langgraph.graph import END, START, MessagesState, StateGraph


def agent(state: MessagesState) -> dict:
    return {"messages": [("ai", "这是一个流式回答的示例。")]}


builder = StateGraph(MessagesState)
builder.add_node("agent", agent)
builder.add_edge(START, "agent")
builder.add_edge("agent", END)
graph = builder.compile()

for chunk in graph.stream(
    {"messages": [("user", "你好")]},
    stream_mode="messages",
):
    message, metadata = chunk
    print(message.content, end="", flush=True)

五种 stream_mode 各看什么

StreamMode types.py:132 在 1.2.20 里包含 values、updates、checkpoints、 tasks、debug、messages、custom 七种； 最常用的是前五种。

mode每个事件是什么适合
values一步结束后的完整 state调试、前端整块刷新
updates节点名 + 该节点返回的局部更新显示「谁改了什么」
messages模型 token + 元数据聊天逐字输出
custom节点内 StreamWriter 写出的任意数据进度、引用、业务事件
checkpoints每次 checkpoint 创建事件持久化调试
tasks任务开始 / 结束 / 错误并行任务监控

流式入口是 Pregel.stream main.py:2705， 异步版是 astream main.py:3117。 多个 mode 可以同时传，事件会带上 mode 标记。

astream_events 与前端契约

需要更细的「链 / 模型 / 工具」级事件时，用 astream_events main.py:3813。 它适合做统一事件总线，但事件更多、体积更大；前端要先约定只消费哪几类。 

async def sse(graph, payload, config):
    async for event in graph.astream_events(payload, config, version="v2"):
        kind = event["event"]
        if kind == "on_chat_model_stream":
            text = event["data"]["chunk"].content
            if text:
                yield f"data: {json.dumps({'type': 'token', 'text': text})}\n\n"
        elif kind == "on_chain_end":
            yield f"data: {json.dumps({'type': 'done'})}\n\n"
先定事件契约，再选 mode

前端只需要 token 就选 messages；要显示节点进度就加 updates； 要业务引用 / 进度条就用 custom。不要把所有事件原样丢给前端。

取消、超时与断线

  • 客户端断开时，服务端要取消流，否则模型调用会继续烧 token。
  • 同步 stream 的生成器关闭会触发取消；异步版用 aclose() 或任务取消。
  • 超时是业务层的总时长，不是「多久没有下一个 chunk」；两者要分开设。
  • 断线重连靠 thread_id + checkpoint，不是靠把已发事件缓存住。

工程实践：三种写法与排查

三种消费方式

for state in graph.stream(inputs, stream_mode="values"):
    print("state", state)

for update in graph.stream(inputs, stream_mode="updates"):
    print("update", update)

for message, meta in graph.stream(inputs, stream_mode="messages"):
    print("token", message.content)

自定义进度

from langgraph.config import get_stream_writer

def node(state: dict) -> dict:
    writer = get_stream_writer()
    writer({"progress": 0.5})
    return {}
现象原因改法
前端重复渲染把 values 当增量用 updates 或前端 diff
没有 token 事件节点没走 LangChain 模型用 chat model 调用
断线后重复执行重新 invoke同 thread 重新订阅
取消后仍烧 token没有传播取消关闭生成器 / 取消任务

再深入一点：实现细节与边界

同时消费多个 mode

for mode, chunk in graph.stream(
    {"messages": [("user", "你好")]},
    stream_mode=["updates", "messages"],
):
    if mode == "updates":
        print("node update:", chunk)
    elif mode == "messages":
        message, metadata = chunk
        print("token:", message.content)

从节点内部发自定义事件

from langgraph.config import get_stream_writer


def retrieve(state: dict) -> dict:
    writer = get_stream_writer()
    writer({"progress": 0.3, "stage": "retrieving"})
    docs = search(state["question"])
    writer({"progress": 0.8, "stage": "reranking"})
    return {"docs": docs}

get_stream_writer config.py:126 只在 stream_mode="custom" 时有输出；没有订阅时是 no-op。

取消与资源释放

  • 同步生成器关闭会触发取消；异步用 aclose() 或任务取消。
  • 取消后仍要保证工具调用有 tool_result，否则下一轮上下文不完整。
  • SSE 断开时，服务端要主动取消上游，而不是等模型跑完。

陷阱与窍门

把 values 当成增量

你会看到前端每次都收到完整 state，重复渲染。因为values 是快照不是 diff。改成用 updates 或在前端做 diff。

messages 模式没有模型调用

你会看到一个 token 都没有。因为节点没有真实模型，或模型没走 LangChain 接口。改成确认模型调用在节点内，并用 LangChain chat model。

断线后重新调用 invoke

你会看到同一会话重复执行。因为断线不是失败，checkpoint 还在。改成用同一个 thread 重新订阅，或从 get_state 继续。
