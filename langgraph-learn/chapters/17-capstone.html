17 · 综合案例：知识库客服（RAG + HITL + 多 Agent）

前面每章只解决一个问题。这一章把它们串起来：一个知识库客服， 能检索文档、查工单、记住用户偏好、写操作前问人、出错能恢复。 我们按「最小闭环 → 加检索 → 加工具 → 加 HITL → 加多 Agent」推进。

读完你能做到

  • 用一张图串起 State、条件边、ToolNode、checkpointer 与 interrupt
  • 把 RAG 检索做成一个节点或工具，并让回答带引用
  • 写操作前用 interrupt() 等人确认
  • 用 Store 记住用户偏好，用 supervisor 路由到不同角色

先说为什么：先跑最小闭环

不要一上来就接向量库、多 Agent、语音。先让「用户问 → 模型答 → 状态可恢复」跑通， 再加检索；检索通了再加工具；工具有副作用了再加 HITL；角色多了再拆多 Agent。 每加一层都保留上一层的验收。

  → 鉴权 / thread_id

装配：State、节点与边

from typing import Annotated, Literal, TypedDict
from operator import add

from langgraph.checkpoint.memory import InMemorySaver
from langgraph.graph import END, START, StateGraph


class State(TypedDict):
    messages: Annotated[list, add]
    route: str
    citations: Annotated[list[str], add]


def supervisor(state: State) -> dict:
    text = state["messages"][-1].content
    route = "researcher" if "手册" in text or "政策" in text else "support"
    return {"route": route}


def researcher(state: State) -> dict:
    # 这里换成真实检索；重点是输出 citations
    return {"citations": ["refund.md"], "messages": [("ai", "检索到退款政策")]}


def support(state: State) -> dict:
    return {"messages": [("ai", "根据资料回答……")]}


def route(state: State) -> Literal["researcher", "support"]:
    return state["route"]  # type: ignore[return-value]


builder = StateGraph(State)
builder.add_node("supervisor", supervisor)
builder.add_node("researcher", researcher)
builder.add_node("support", support)
builder.add_edge(START, "supervisor")
builder.add_conditional_edges("supervisor", route, ["researcher", "support"])
builder.add_edge("researcher", "support")
builder.add_edge("support", END)

graph = builder.compile(checkpointer=InMemorySaver())

工具：检索与工单

检索可以做成节点（总是执行）或工具（模型决定是否调用）。 知识库问答通常用节点，保证每次回答都有上下文； 订单查询用工具，让模型按需调用。工具结果要以 ToolMessage 回到 messages。

HITL：写操作先问人

from langgraph.types import interrupt


def approval(state: dict) -> dict:
    ok = interrupt({"question": "是否创建退款工单？"})
    return {"messages": [("ai", "已创建" if ok else "已取消")]}

图必须挂 checkpointer；恢复时用同一个 thread_id 调 graph.invoke(Command(resume=True), config)。 副作用放在 interrupt 之后，避免重入时重复执行。

记忆：会话与用户偏好

对话历史交给 checkpointer；用户偏好（语气、语言、租户）交给 Store。 在 supervisor 之前读一次偏好，写进系统提示或 state，不要每轮都检索。

流式与前端事件

前端至少需要三类事件：token、节点进度、待确认项。 用 stream_mode=["messages", "updates"] 或 astream_events，再把 interrupt 事件渲染成确认框。 断线重连靠 thread_id + checkpoint，不要重新提交。

部署与验收

  • checkpointer 用 Postgres；Store 用 PostgresStore。
  • 同一 thread 串行，重复提交返回 409 或排队。
  • 健康检查覆盖数据库、checkpoint 表与模型连通性。
  • 验收：有答案、无答案、需要工具、需要确认、断线恢复、多租户隔离。

陷阱与窍门

先接多 Agent 再补状态

你会看到路由与 state 打架。因为状态边界没定。改成先单 Agent 跑通，再加 supervisor。

检索节点每次都重跑

你会看到延迟与成本上涨。因为工具循环里重复检索。改成把检索放在工具循环外，或加缓存。

HITL 恢复换了 thread

你会看到找不到暂停点。因为中断按 thread 保存。改成恢复使用同一个 config。
