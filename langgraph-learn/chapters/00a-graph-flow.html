00A · 图执行实验室

读图最容易断片的地方，是「这一步之后为什么走那条边」。这一页把一次 invoke 拆成可播放的节点：从输入、START、模型节点、条件路由、工具节点， 到 checkpointer、interrupt 与 END，每一步都能看到 state 与 next 的变化。

这一页怎么用

  • 用 L1 看清最小图：START → 节点 → END，state 在哪一步合并
  • 用 L2 看清条件边与工具循环：tool_calls 如何把图带回模型节点
  • 用 L3 看清 checkpointer 与 interrupt：暂停不是结束，恢复从哪个 checkpoint 继续
  • 每一步都能点回对应章节与源码入口

最小链路：START → node → END

        

          L1 没有任何模型与工具：输入进入 START，节点读 state、返回 partial state，
          执行器合并后走到 END。这条链路只有 6 个观察点，但已经能看清「状态在哪一步变」。
        

        

          

            
节点它做什么输出给谁

            
              
Input调用 invoke，传入初始 stateSTART

              
START虚拟入口，找到第一条边Agent

              
Agent读 state，返回要更新的字段Route

              
Route条件边决定继续还是结束END

              
END虚拟出口，执行器收尾Result

              
Result返回最终 state调用方

            
          

        


        
工程化：条件边、工具与循环

        

          L2 新增 Checkpointer、ToolNode、ToolRoute、
          Subgraph、Stream。真正改变控制流的是工具循环：
          模型返回 tool_calls → ToolRoute 指向 ToolNode →
          工具结果写回消息 → 回到 Agent 再推理一次。
        

        

          

            
L2 的层插在哪它改变什么

            
              
Checkpointer +L2每次 superstep 之后把 state 写成 checkpoint，可按 thread_id 恢复

              
ToolNode +L2条件边的一支执行工具，把 ToolMessage 写回 messages

              
ToolRoute +L2Agent 之后有 tool_calls 去工具，没有则结束

              
Subgraph +L2可插在任意节点位置把一张图当成一个节点，状态按 schema 映射

              
Stream +L2执行器外层把内部 step 变成可观察的事件流

            
          

        


        
生产化：checkpoint、interrupt 与恢复

        

          L3 再加 API、Auth、Store、Retry、
          Interrupt、Postgres、Observe、Deploy。
          最关键的是 Interrupt：它把执行停在 checkpoint 上，
          恢复时不是从头跑，而是带着 Command(resume=...) 从暂停点继续。
        

        

          没有 checkpointer 就没有 interrupt
          

            暂停需要把「停在哪、state 是什么、哪个节点在等」写进持久化存储。
            只挂 interrupt() 不挂 checkpointer，恢复时框架找不到暂停点。
