24 · 案例二：多轮知识库客服

需求：用户连续提问，系统能检索知识库、记住用户偏好、每轮回答带引用。 这个案例把 checkpointer（短期记忆）、Store（长期偏好）与检索节点组合起来。

读完你能做到

  • 用同一个 thread_id 跑多轮对话
  • 用 Store 记住跨 thread 的用户偏好
  • 把检索做成节点，并让回答带引用
  • 区分「会话历史」「用户偏好」「知识库」三类数据

先说为什么：不要把偏好塞进 messages

偏好会随着对话被压缩、被裁掉；而每轮都重新说一遍又浪费 token。 正确做法是：对话历史进 checkpointer，偏好进 Store，知识库进检索服务。

案例：一轮问答

user_id=alice, thread_id=t-1
用户：退款政策是什么？
→ 读偏好（简洁）
→ 检索 refund.md
→ 回答 + 引用

架构：读偏好 → 检索 → 回答

START
  → load_preference（Store）
  → retrieve（知识库）
  → answer（模型 / 假模型）
  → END

装配：State、Store 与 checkpointer

from typing import Annotated, TypedDict
from operator import add

from langgraph.checkpoint.memory import InMemorySaver
from langgraph.graph import END, START, StateGraph
from langgraph.store.memory import InMemoryStore


class State(TypedDict):
    messages: Annotated[list, add]
    question: str
    citations: Annotated[list[str], add]
    tone: str


store = InMemoryStore()


def load_preference(state: State, config, store) -> dict:
    user_id = config["configurable"]["user_id"]
    item = store.get(("users", user_id), "preference")
    return {"tone": item.value["tone"] if item else "default"}


def retrieve(state: State) -> dict:
    # 换成真实向量库；这里用固定片段模拟
    return {"citations": ["refund.md"], "question": state["question"]}


def answer(state: State) -> dict:
    return {"messages": [("ai", f'[{state["tone"]}] 根据 refund.md：7 天无理由退款')]}


builder = StateGraph(State)
builder.add_node("load_preference", load_preference)
builder.add_node("retrieve", retrieve)
builder.add_node("answer", answer)
builder.add_edge(START, "load_preference")
builder.add_edge("load_preference", "retrieve")
builder.add_edge("retrieve", "answer")
builder.add_edge("answer", END)

graph = builder.compile(checkpointer=InMemorySaver(), store=store)

store 与 config 是节点可请求的运行时参数； compile(store=...) 之后框架会注入。

多轮：同一个 thread

config = {"configurable": {"thread_id": "t-1", "user_id": "alice"}}

graph.invoke({"messages": [("user", "退款政策？")], "question": "退款", "citations": [], "tone": ""}, config)
graph.invoke({"messages": [("user", "那运费呢？")], "question": "运费", "citations": [], "tone": ""}, config)

第二轮会自动加载第一轮 checkpoint；换一个 thread_id 就是新会话， 但同一个 user_id 仍然共享 Store 偏好。

流式与引用

前端至少需要「引用」与「token」两类事件。先发 citations，再发 token： 用户不必等回答结束才知道来源。 

yield {"event": "citations", "data": state["citations"]}
for token in answer_stream:
    yield {"event": "token", "data": token}

陷阱与窍门

偏好存在 messages 里

你会看到压缩后偏好消失。因为messages 会被裁剪。改成Store。

换 thread 后偏好也丢了

你会看到新会话回到默认语气。因为偏好被误放进了 checkpoint。改成Store 的 key 只按 user，不按 thread。

检索每轮都重跑

你会看到延迟与成本上涨。因为检索放在工具循环里。改成检索节点放循环外，或缓存结果。

自检三问

  1. 会话历史、用户偏好、知识库分别存在哪里？
  2. 为什么偏好不能跟 thread_id 绑定？
  3. 引用事件应该什么时候发？

30 分钟动手练习

  1. 用两个 thread 跑同一用户，确认偏好共享、历史不共享。
  2. 把检索节点换成真实向量库，返回 2 条引用。
  3. 用假模型跑一轮，断言 citations 出现在回答之前。
